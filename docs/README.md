# 片场 V2 文档入口

根目录只保留当前开发需要持续维护的文档。历史实现记录、旧提案和被合并的详细参考资料统一放在 `archive/`，不再与当前设计并列展示。

## 活跃文档

| 文档 | 用途 | 何时阅读 |
|---|---|---|
| [产品设计](./V2_PRODUCT_DESIGN.md) | 产品目标、用户流程、功能边界和验收原则 | 评审产品行为或新增功能前 |
| [系统架构](./V2_SYSTEM_ARCHITECTURE.md) | 模块、数据、状态、事件、Provider 和运行边界 | 设计技术方案或修改后端前 |
| [创作中心](./V2_CREATION_CENTER_DESIGN.md) | 对话、需求、候选、确认、附件和智能体设计 | 修改创作流程或智能体前 |
| [实现状态](./V2_IMPLEMENTATION_STATUS.md) | 已完成、部分完成、待确认和未开始能力 | 判断当前代码能做什么时 |
| [交接上下文](./HANDOFF_CONTEXT.md) | 当前运行状态、约束和下一步 | 新任务或恢复开发时首先阅读 |

## 归档目录

| 目录 | 内容 |
|---|---|
| [`archive/implementation-notes/`](./archive/implementation-notes/) | 每个历史 Sprint 的实现证据与验收记录 |
| [`archive/proposals/`](./archive/proposals/) | 待确认或已完成使命的独立提案 |
| [`archive/reference/`](./archive/reference/) | 已合并进系统架构的详细数据、状态和旧架构资料 |

归档文件仍可通过活跃文档中的链接访问，但不作为当前产品状态的权威入口。功能是否已经实现，以 [实现状态](./V2_IMPLEMENTATION_STATUS.md) 和代码测试为准。

## 维护规则

1. 新功能优先更新对应活跃文档，不再默认新增一份永久的根目录文档。
2. 仅当方案需要独立评审时创建提案；确认并合并后移入 `archive/proposals/`。
3. 短期实现记录写入交接文档的“最近变更”，稳定后移入实现状态或 Git 历史。
4. `HANDOFF_CONTEXT.md` 只保留当前事实、约束和最近变更，不累积完整 Sprint 日志。
5. 归档资料不得覆盖活跃文档；发现冲突时以活跃文档和当前代码为准。
6. 所有移动使用 Git 重命名并修复相对链接，不删除仍有审计价值的历史资料。
