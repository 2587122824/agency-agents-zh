# V2 配音与剪辑完善路线图

> 状态：活跃实施基线  
> 更新日期：2026-07-26  
> 范围：配音、字幕、时间线编辑、BGM、音频质检、授权声音复刻与重试

## 1. 目标与边界

本路线图把“能生成一条旁白并合成成片”继续完善为可选择、可试听、可编辑、可质检、可重试且可审计的音频剪辑闭环。页面可见不等于能力可用；完成状态必须同时具备版本化合同、确定性校验、自动化测试，以及涉及真实供应商时的真实调用证据。

开发环境不兼容旧合同或旧开发数据。合同变化通过显式迁移或重建测试数据落地，不在运行时代码中增加旧版兼容分支。所有付费调用、声音复刻授权、重试费用和最终人工放行均由用户显式确认。

## 3. 字幕闭环合同

旁白模式必须同时创建 `project.voiceover` 与 `project.subtitles`，二者都是 `project.timeline` 的必需父节点。静音模式不得创建其中任一节点。

字幕 cue 只来源于已确认 Creative Brief 的 `voiceover/dialogue` 脚本段和 `narrative_beats.target_duration_ms`。生成器按节拍顺序切分文本，保证 cue 非空、互不重叠、时间严格递增且不超过成片时长。输出为 UTF-8 SRT，并登记内容哈希、cue 数和最终时点。

字幕素材必须先通过确定性 SRT 探测和显式人工内容审核。旁白剪辑项目要求当前快照恰好一条已批准配音和一份已批准字幕；剪辑助理将它们分别冻结到音频轨和字幕轨。字幕轨当前只允许从零开始、无空隙、单条 `burn_in` 渲染。

本机渲染器使用 libass `subtitles` 滤镜与冻结样式烧录字幕。Windows 环境从字幕文件所在目录启动 FFmpeg 并仅传字幕文件名，避免盘符冒号被滤镜解析为选项分隔符。输入文件在渲染前继续执行路径、哈希和合同复验。

## 4. 实施顺序

1. CosyVoice 真实验收命令、只读 API、系统配置页二次确认和不可变验收记录已完成；配置 v56 已通过 V1 显式迁移补齐 API Key，只读预检为 `ready_for_paid_validation` 且不联网。仍需用户显式授权一次真实付费验收。
2. 音色、语速、音量和期望时长已升级为版本化音频执行合同；制作准备选择、请求冻结和时长门禁已完成，真实试听随 CosyVoice 凭据一并验收。
3. 时间线缩放、拖放、波形缓存、淡入淡出和音量包络合同已完成。
4. BGM 权利确认、循环/裁切、旁白区间 ducking、响度目标和 limiter 执行合同已完成；实际测量证据进入下一步 QC。
5. 确定性 WAV/成片音频 QC 与人工试听确认首期闭环已完成。
6. 授权声音复刻实体、精确 TTS/字幕重试及依赖级费用确认批量重试首期闭环已完成。
7. 当前唯一阻塞验收是取得用户明确授权后执行一次真实 CosyVoice 付费合成，并保存供应商请求与真实 WAV 探测证据。

每一步单独更新实现状态、测试基线和交接文档；不得因为后续能力尚未完成而把已完成的字幕闭环标成完整音频剪辑能力。

只读检查：

```powershell
python -m v2.scripts.validate_cosyvoice_connection
```

真实付费验收必须同时满足：已发布配置存在 API Key、`V2_EXTERNAL_PROVIDER_EXECUTION_ENABLED=true`，并由操作者显式执行：

```powershell
python -m v2.scripts.validate_cosyvoice_connection --confirm-paid-call
```

工具与系统配置页只输出配置/工作流标识、凭据状态、验收文本哈希、供应商请求 ID、非敏感用量和 WAV 探测事实。系统配置页先冻结当前配置哈希、默认音色、语速、音量与文本哈希，再通过单独勾选确认执行一次；成功或已尝试的失败均写入不可变验收记录。任何路径都不得输出 API Key；缺凭据或执行授权时 `network_probe_performed=false`，不得创建验收尝试。
