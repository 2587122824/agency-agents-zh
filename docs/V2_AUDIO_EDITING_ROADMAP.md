# V2 配音与剪辑完善路线图

> 状态：活跃实施基线  
> 更新日期：2026-07-26  
> 范围：配音、字幕、时间线编辑、BGM、音频质检、授权声音复刻与重试

## 1. 目标与边界

本路线图把“能生成一条旁白并合成成片”继续完善为可选择、可试听、可编辑、可质检、可重试且可审计的音频剪辑闭环。页面可见不等于能力可用；完成状态必须同时具备版本化合同、确定性校验、自动化测试，以及涉及真实供应商时的真实调用证据。

开发环境不兼容旧合同或旧开发数据。合同变化通过显式迁移或重建测试数据落地，不在运行时代码中增加旧版兼容分支。所有付费调用、声音复刻授权、重试费用和最终人工放行均由用户显式确认。

## 3. 字幕闭环合同

旁白模式必须同时创建 `project.voiceover` 与 `project.subtitles`，二者都是 `project.timeline` 的必需父节点。静音模式不得创建其中任一节点。

字幕 cue 只来源于已确认 Creative Brief 的 `voiceover/dialogue` 脚本段和 `narrative_beats.target_duration_ms`。生成器按节拍顺序切分文本，保证 cue 非空、互不重叠、时间严格递增且不超过成片时长。输出为 UTF-8 SRT，并登记内容哈希、cue 数和最终时点。

字幕素材必须先通过确定性 SRT 探测和显式人工内容审核。旁白剪辑项目要求当前快照恰好一条已批准配音和一份已批准字幕；剪辑助理将它们分别冻结到音频轨和字幕轨。字幕轨当前只允许从零开始、无空隙、单条 `burn_in` 渲染。

本机渲染器使用 libass `subtitles` 滤镜与冻结样式烧录字幕。Windows 环境从字幕文件所在目录启动 FFmpeg 并仅传字幕文件名，避免盘符冒号被滤镜解析为选项分隔符。输入文件在渲染前继续执行路径、哈希和合同复验。

## 4. 实施顺序

1. 补充只读的 CosyVoice 真实验收命令；缺少 API Key 时明确拒绝，不创建费用或伪造成功证据。
2. 将音色、语速、音量和期望时长升级为版本化音频执行合同，并完成制作准备选择与试听。
3. 建立时间线缩放、拖放、波形缓存、转场和音量包络合同。
4. 增加 BGM 素材、ducking、响度和削波控制。
5. 增加确定性 WAV QC 与人工试听确认。
6. 建立授权声音复刻实体、精确 TTS/字幕重试及依赖级费用确认批量重试。

每一步单独更新实现状态、测试基线和交接文档；不得因为后续能力尚未完成而把已完成的字幕闭环标成完整音频剪辑能力。
