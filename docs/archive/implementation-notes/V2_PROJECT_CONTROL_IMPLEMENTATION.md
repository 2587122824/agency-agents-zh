# 片场 V2 项目控制台实现

版本：v0.6

状态：已实现

实现目录：`v2/backend/app/control/`、`v2/backend/app/orchestration/project_state.py`、`v2/frontend/src/pages/DashboardPage.tsx`、`v2/frontend/src/pages/ProjectControlPage.tsx`

## 1. 范围

项目控制台为用户提供跨阶段的只读生产视图。它汇总项目、方案、快照、执行、素材、质量、剪辑、交付、成本和事件事实，不写数据库，不调用 Worker 或供应商，也不提供自动重试、状态修复或路由替换。

## 2. 状态权威

响应同时包含：

- `persisted_status`：Project 表中的权威状态。
- `evaluated_stage`：由现有权威记录计算的页面导航阶段。

阶段投影由不依赖 ORM 的纯函数 `evaluate_project_state(ProjectStateFacts)` 计算，不写回 Project。完成交付、交付尝试、时间线、质量状态、生产执行、快照和方案按从后到前的优先级判断，因此历史阻断不会遮盖已经成立的后续权威事实。活动快照存在时优先于最新历史快照。

该评估器不执行命令、不写事件，也不根据结果自动修改 `Project.status`。权威写入由独立项目状态转移器负责；两者职责不能合并。完整边界见 [V2 项目状态评估器实现](./V2_PROJECT_STATE_EVALUATOR_IMPLEMENTATION.md) 与 [V2 权威项目状态转移器实现](./V2_PROJECT_STATE_TRANSITION_IMPLEMENTATION.md)。

## 3. 汇总事实

控制台展示：

- 活动方案和活动或最新生产快照。
- 当前快照内 WorkItem 与 Asset 状态计数。
- 快照、工作项、QC 和交付的结构化阻断证据。
- 按币种分离的预计、扣费、调整、退款和待对账事件。
- WorkAttempt 冻结请求清单中的供应商、适配器和工作流，以及实际任务 ID。
- 最近 20 条持久化 ProjectEvent。
- 可分页的完整 ProjectEvent 信封和全部逐笔 CostEvent。
- 由当前事实确定的唯一下一步页面、确认等级和费用边界。
- Project 状态行版本、触发器、操作者、时间和首次 blocked 责任证据。

错误文案仅用于展示，不参与阻断类型、路由或阶段判断。

## 4. API

```text
GET /api/v1/project-controls
GET /api/v1/projects/{project_id}/control-center
GET /api/v1/projects/{project_id}/audit-ledger?limit=50&before_sequence={sequence}
```

列表接口用于首页总控，详情接口用于单项目证据视图，账本接口使用项目内事件序号确定性分页。三者都是只读 GET，不创建命令回执、事件或费用记录。

## 4.1 Repository 边界

只读 `ControlRepository` 负责精确读取：

- 活动方案、项目快照和显式活动快照 ID。
- 当前权威快照范围内的 WorkItem、WorkAttempt、Asset、DAGNode 与 blocked QC 证据。
- 最新时间线、最新交付尝试、规划候选存在性和最近 20 条项目事件。
- 原始 CostEvent 与项目更新时间排序。

Control 应用服务继续负责权威快照选择、阻塞证据结构、费用按币种聚合和实际路由展示，并将显式事实交给纯项目状态评估器计算阶段与下一步。Repository 和评估器都不写项目状态、不执行下一步、不根据错误文案分类，也不把未确认费用计入确认金额。

## 5. 页面

首页 `/` 显示服务状态、项目数量、待审核数量、阻断总数和项目生产列表。每个项目直接展示阶段、工作项进度、活动方案/快照、阻断数量与下一步，并进入 `/projects/{project_id}/control`。

首页默认排除归档项目，并提供显式“已归档”视图和恢复入口。归档/恢复是独立项目命令，不属于只读 Control 投影；Control 只读取 `archived_at/archived_by`，归档详情页隐藏继续阶段按钮但保留费用与事件入口。

项目详情展示阶段、状态版本/来源、首次阻断来源、指标、分币种成本、实际执行路由和最近事件。下一步按钮只导航到现有工作页面，不直接执行业务命令。

`/projects/{project_id}/audit` 展示完整事件信封、分币种费用汇总和逐笔费用事实。页面一次读取 50 条事件，只有用户点击“读取更早事件”才使用后端返回的下一游标继续读取。单笔费用不合并、不换算，待对账或争议状态不计入已确认金额。

阻断、事件、项目状态、制作方案状态、制作步骤状态、执行状态、状态来源、操作者类型和责任对象主要信息使用集中式中文展示词典。词典只接受精确结构化值，不解析 message/Error 文本；未知值使用中性中文说明。原始代码、类型、消息、ID、关联关系和数据仍保留在默认收起的技术详情。项目控制台区块眉题也使用普通中文，不把英文内部术语作为主界面导航信息。

## 6. 验收

- 新项目显示需求确认阶段和继续确认需求。
- 未连接适配器失败后显示精确供应商路由、错误码和结构化阻断。
- 已验证最终交付显示完成阶段与下载入口。
- 控制台查询前后数据库状态不发生变化。
- 费用不跨币种合并，未确认事件不进入确认金额。
- 前端桌面和手机布局无页面级横向溢出。
- 查询和页面不引入供应商调用、重试、兜底或隐藏状态转换。
- 纯评估器重复读取相同事实得到相同阶段与下一步，且不修改输入计数。
- 活动快照存在时，最新历史快照不能覆盖其阶段判断。
- blocked 项目显示首次原因码和责任聚合；后续诊断事件不能覆盖首次来源。
- 事件分页不重复、不跳回较新序号，查询前后 ProjectEvent 和 CostEvent 数量不变。
- 当前阻断和最近事件主要信息不直接展示英文代码或英文历史消息。
- 项目概览和实际执行路由不直接展示内部状态、触发器、动作代码、责任对象 ID 或执行指纹；技术详情仍可核对全部原始事实。
