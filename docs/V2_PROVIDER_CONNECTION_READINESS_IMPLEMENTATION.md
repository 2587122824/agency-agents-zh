# 片场 V2 生成服务连接准备实现

> 更新日期：2026-07-17
>
> 本阶段只完善本地只读检查和配置编辑体验。没有读取或写入密钥原文，没有联网探测、供应商任务或费用。

## 1. 目标

设置页必须准确回答“还差哪一步才能连接”，不能用一个总状态掩盖多个独立条件。每个已发布供应商版本分别检查：

1. 后端是否注册了精确执行组件。
2. 该版本的工作流输入是否符合当前适配器合同。
3. 后端是否可以读取配置引用的密钥。
4. 外部真实执行是否已显式授权。

四项检查都是本地事实。即使全部通过，也只表示可以开始一次经用户确认的真实连通测试，不表示供应商账号、余额或工作流在线。

## 2. 只读 API 合同

`GET /api/v1/system-config/provider-readiness` 为每个供应商返回：

- `adapter_registered`、`credential_state`、`execution_enabled`；
- `configuration_ready` 和不兼容项数量；
- 去重后的结构化不兼容代码，仅放在技术详情；
- 唯一的 `next_action`，供界面显示普通用户可理解的下一步；
- 总状态 `connected | adapter_not_connected | configuration_not_ready | credential_not_ready | execution_disabled`。

状态优先级固定为：执行组件、生成配置、后端密钥、执行授权、就绪。后面的条件不会覆盖前面的确定性阻断，但界面同时展示全部四项检查，因此用户可以一次看清所有缺口。

接口不返回密钥值、环境变量名或完整凭据引用，不发起网络请求，也不修改配置验证报告。

## 3. 单一 RunningHub 合同校验器

`providers/runninghub_contract.py` 是 RunningHub NodeInfoList 的唯一确定性规则来源。配置发布校验和连接准备检查共用同一函数，覆盖：

- 映射列表非空和字段完整；
- 节点 ID 与字段路径不重复；
- 只接受声明的 Shot、视频规格、时长、种子、单父图片和 `literal:<JSON>` 来源；
- `source_image` 只适用于视频生成；
- 首帧视频必须恰好声明一个 `source_image`。

历史已发布版本不会被重新写入或自动升级。旧 `{{prompt}}`、`{{reference_image}}` 和普通文本常量会被只读识别为不兼容，并要求用户复制为新草稿后显式修订、校验和发布。

## 4. 设置页交互

生成服务连接卡片显示四项检查和一条明确下一步，并可直接定位对应配置版本。技术类型、能力和错误代码仍收在折叠详情中。

工作流输入编辑器不再要求用户手写值来源：

- “镜头动作”“镜头构图”“上一步生成的关键帧”“画面宽度”等使用下拉选择；
- 固定值单独填写，界面按文本、数字、开关或结构化数据生成严格 `literal:<JSON>`；
- 历史不支持的来源显示为“旧格式（需要更换）”，不自动转换；
- 生成类型使用“生成图片”“首帧生成视频”“文字生成语音”等普通名称。

节点 ID、输入字段和工作流 ID 仍是 RunningHub 工作流的精确技术事实，不能由系统猜测或隐藏替换。

## 5. 安全与确认边界

- 密钥原文仍只存在于后端环境，数据库只保存 `env://` 引用。
- `V2_CREDENTIAL_ENV_ALLOWLIST` 继续限制后端允许读取的变量名。
- `V2_EXTERNAL_PROVIDER_EXECUTION_ENABLED` 默认关闭。
- 查看连接准备状态、复制配置、编辑草稿和执行确定性校验均不联网、不产生费用。
- 发布新配置、开启真实执行和第一次联网测试保持独立确认；本阶段没有自动执行其中任何一步。

## 6. 验收证据

- 合同正确、密钥可读但执行关闭时，下一步为“开启执行授权”。
- 历史旧占位符版本优先显示“生成配置需要更新”，同时保留密钥和授权检查结果。
- 连接状态查询前后历史工作流内容完全一致。
- API 响应不包含密钥值或环境变量名。
- 固定值编辑生成严格 `literal:<JSON>`，旧来源不会被自动改写。
- 桌面和移动端连接检查及工作流编辑器无横向溢出。

## 7. 未包含能力

- RunningHub 网络连通、账号、余额或工作流在线检查。
- 旧配置自动迁移、提示词合成、字段猜测或工作流替换。
- 密钥管理台、密钥原文 API 或前端密钥输入框。
- 自动发布、自动开启执行、真实任务、重试、对账或降级。
